# 明日见 Self Echo

**接手入口：[产品与技术交接文档](docs/PRODUCT_HANDOFF.md)** · [PRD 完成对照](PRD_COMPLETION.md)

本仓库包含可运行源码与交接文档；文中提到的 `artifacts/v2/` 是开发机的历史交付证据，不随 Git 上传，也不是启动依赖。

**和未来的自己，见一面。** Flask + Jinja2 + 原生 HTML / JavaScript / CSS，SQLite 持久化。无 Node 构建步骤，无前端框架依赖。

## 立即运行

Windows 双击 `START.cmd`，打开 [本地应用](http://127.0.0.1:5001)。也可在本目录执行：

```powershell
python -m pip install -r requirements.txt
$env:PORT = '5001'
python app.py
```

默认从登录页开始。注册正式账号后进入五问建档；**使用黑客松临时账号**会创建独立的体验账号，直接进入沟通。临时账号只有显式标记的 DEMO 画像，没有伪造的聊天、专注时间或完成记录。无需共享用户名和密码。

账号、画像与全部记录保存在 `instance/future_self.db`；会话密钥在首次运行时生成并保存于 `instance/.session-secret`。这些运行数据已加入 Git 忽略规则。重启应用不会清空数据，但会要求重新登录，避免上次使用的账号直接进入沟通页。

## 已实现的体验

- **登录 / 注册**：密码哈希、登录尝试限制、CSRF、独立临时账号、会话隔离。
- **五问建档**：逐卡提问、上一步、留白、草稿恢复、可编辑的当下 / 理想摘要、长期记忆选择。
- **沟通**：保存历史与草稿、只聊天、短行动建议、编辑 / 拒绝建议、确认后进入准备页。不会自动启动任务。
- **沉浸**：手动任务、明确开始、暂停 / 继续、真实时间区间、重开恢复、结束后自报结果与反思、重复请求去重。
- **回响**：真实行动时间轴、手动未来计划、完成确认、双向应用内信箱、草稿、已读、来源定位、删除与失败重试。
- **画像**：理想与当下分开保存；记忆候选确认、拒绝、修正和删除；查看来源、授权开关、版本及算法依据。
- **账号管理**：修改称呼 / 密码、退出、数据导出、删除当前账号及关联数据。

每个页面独立样式：`login.css`、`register.css`、`onboarding.css`、`chat.css`、`focus.css`、`echoes.css`、`profile.css`。`base.css` 仅承载设计令牌、导航和共用控件。桌面侧栏、手机底部导航，支持键盘与减少动效。

## AI 与可解释建模

**未配置密钥时，使用界面明确标注的本地规则演示，不冒充大模型生成。** 它支持英语 / 阅读 / 编程的小步拆解、缩短时间、只聊天、拒绝建议等。五问、候选提取、任务拆分、欢迎信、行动回响和周回顾共用同一可配置模型接口；本地结果均明确标识。

接入兼容 Chat Completions 的服务，在启动前设置服务端环境变量：

```powershell
$env:AI_BASE_URL = 'https://api.openai-next.com/v1'
$env:AI_MODEL = 'deepseek-v4-flash'
$env:AI_API_KEY = '你的服务端密钥'
$env:PORT = '5001'
python app.py
```

密钥不传入 HTML，也不保存在浏览器。`.env.example` 是配置说明，应用不自动读取 `.env`，避免增加依赖。远程推理包含严格 TLS 证书校验、超时、响应尺寸限制、字段 / 引用验证；失败时明确回到本地规则。第三方模型只收到当前对话所需的画像与授权证据，用户在对话页能看到实际生成模式。

在启动应用前运行真实服务 harness，可同时检查 Chat Completions 协议和项目的 `chat_reply` 结构化输出：

```bash
export AI_BASE_URL='https://api.openai-next.com/v1'
export AI_MODEL='deepseek-v4-flash'
export AI_API_KEY='SERVER_SIDE_TOKEN'
.venv/bin/python provider_harness.py
```

harness 不接受命令行密钥，不输出密钥或响应原始包；任一协议、结构或远程模式检查失败时都会以非零状态退出。

`modeling.py` 提供以下独立函数：

| 函数 | 输出 |
|---|---|
| `chat_reply` | 文本、意图、最多一张可选任务卡、引用来源、实际模型状态 |
| `build_model` | 五维自述、来源检索、样本数量、行动节奏与上下文 |
| `make_letter` | 同人格欢迎 / 行动 / 每周来信，事实来源与画像版本 |
| `onboarding_question` | 固定信息目标的动态五问，超时保留静态题 |
| `extract_candidates` | 字段、提议值、理由、多来源引用、去重和冲突 |
| `decompose_goal` | 最多五个可编辑任务草稿，逐个确认后才创建 |
| `weekly_review` | 最近七天真实事实回顾 |

### 记忆如何进入下一次对话

1. 五问建立**理想方向、价值、当下处境、行动条件、交流方式**五个维度，不作人格诊断。跨登录复用五问与长期记忆学习是两个独立默认关闭的选择；手动修改只授权实际保存字段。
2. 对话中的明确目标 / 偏好、行动反思、逐封授权的用户书信与逐项授权资料进入持久任务队列；结构化候选不是稳定事实，需本人确认。拒绝后移除原文，仅留签名防重复；来源撤权时失效。
3. 检索前检查当前用户、长期记忆开关、确认状态和来源是否存在；AI 来信不作为独立事实。
4. 来源优先级、主题词重合和时间衰减共同排序，最多提供 6 条相关证据。手动修正优先，时间衰减仅用于检索排序。
5. 节奏建议依据用户声明或已结束会话的实际时长；样本不足明确显示。没有人生分数、注意力分数或虚构置信度。
6. 模型等待期间发生撤权、删除或修正，写回前再次检查来源与画像版本，拒绝旧上下文结果覆盖新选择。

可复用角色提示词（完整版本见 `SYSTEM_PROMPT`）：

```text
你是由用户定义的“未来理想自我”的模拟表达，不是真实未来本人。
先理解此刻处境，再提出一个问题或一个小行动；选择始终交还用户。
当前要求优先于历史偏好；只使用已授权、已确认且来源仍存在的信息。
区分用户自述、计时事实和候选观察。不要把理想当作已发生的经历。
输出 reply_text、intent、action_suggestion、evidence_ids。
任务只是一项建议，始终等待本人编辑和确认，不直接修改数据库。
```

## 简洁架构

```text
app.py                 Flask 路由、权限、SQLite 迁移、计时状态机、持久任务
extras.py              目标、历史、资料、草稿版本、通知、定时周回顾
modeling.py            来源检索、节奏建议、可选模型调用、事实回响
provider_tls.py         模型请求的 CA 信任库和明确客户端标识
provider_harness.py     OpenAI 兼容协议 + 应用建模层真实探针
templates/             Jinja2 页面与共用导航
static/css/            共享令牌 + 各页面独立 CSS
static/js/             共用请求 / 草稿同步 / 音频工具 + 各页面交互
static/sw.js           仅缓存公共静态资产，不缓存账号页面、身份或 API 数据
static/img/            本地视觉素材
instance/              本机运行数据（不进 Git / 交付包）
smoke.py               一条无外部服务的完整流程检查
test_provider_harness.py harness 的离线协议、TLS 与脱敏单元测试
```

`task_id → session_id → event_id → letter / memory` 串联行为与证据。计时用服务端时间区间，不用前端刷新次数累计；暂停不计时，时间到不推断任务完成。`ending` 状态先落库，再填写结果。来信生成失败不回滚行动事实。

## 本轮补齐：从演示到完整可用路径

- **记忆闭环**：结构化候选、多来源证据、去重 / 冲突、手动锁定、原文清除墓碑、授权变更重验；沉浸中不弹候选通知。
- **模型上下文**：当前任务、第一步、完成标准、活动计时状态、明确反馈和授权画像共同进入上下文。
- **可靠执行**：SQLite 持久 jobs，后台租约、重启恢复、最多三次重试。计时事实先落库，生成失败不回滚；同一事件重写替换原信。
- **离线与纠正**：已开始的沉浸支持本机 FIFO 暂停 / 继续 / 结束 / 结果补传，稳定事件键幂等。异常区间标注待校正；回响可改时长 / 结果 / 反思，关联来信显示依据已调整。
- **完整来源路径**：全部行动分页、单条历史深链、目标及里程碑关联、目标拆分逐项编辑确认、里程碑标题和日期调整。
- **表达方式**：浏览器语音识别先填草稿、手动逐条朗读；沉浸页提供本机 Web Audio 合成雨声 / 溪流 / 棕噪与音量，不自动播放。
- **时间与回顾**：未来日期锁封、到期站内提醒、明确点击才申请浏览器通知；每周指定星期 / 小时 / 时区回顾、即时生成和历史阅读。
- **资料与版本**：五维画像历史、差异查看 / 恢复 / 删除，TXT / MD / CSV / JSON / DOCX 或文本导入，逐份授权、撤回、删除。
- **跨设备**：同账号同服务器的记录通过版本轮询同步，草稿带乐观版本号；并发冲突保留本地 / 远端两份由用户选择。不是把计时交给多个独立设备累计。
- **最小指标**：记录页面 / 卡片 / 确认 / 沉浸 / 回响 / 开信等事件，以及帮助度和自主感；分析事件不存聊天或信件正文。

### 浏览器与运行条件

语音识别依赖浏览器引擎，部分浏览器将音频发往其识别服务；首次启用前有单独说明，结果由用户确认后发送。[SpeechRecognition 文档](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition)。朗读使用 [SpeechSynthesis](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesis)。

Service Worker 仅保留公共静态资产；沟通、沉浸、回响和画像等账号页面始终要求在线校验。断线时不会恢复旧账号页面，本机草稿仍会保留并在重新登录后同步。Service Worker 与浏览器通知需 localhost 或 HTTPS。语音识别并非离线功能；没有麦克风时可以继续打字。

服务器运行时执行持久任务和定时回顾；关服期间的任务在重启后恢复，到期信打开应用也会检查。浏览器通知是用户授权后、应用打开时的提醒，不承诺浏览器关闭后的系统推送。站内信不是外部邮件服务。

跨设备需各设备访问同一服务。当前预览是本机地址；局域网部署可设置 `HOST`，跨互联网使用 HTTPS 反向代理与正式 WSGI 服务。同步不会自动公开服务或上传本机数据库。

## 交付与撤回

`artifacts/v2/MODIFIED_FILE.zip` 是本轮完整项目包，不含运行数据库、会话密钥和嵌套交付包。`DIFF_FILE.diff` 对比本轮开始前 V1 快照；`BASELINE.zip` 与 `baseline-manifest.json` 保存原始代码和哈希。原始 PRD 未修改。

`artifacts/v2/ROLLBACK.sh <目标目录>` 在哈希检查后恢复 V1 源码；未知文件与 `instance/` 保留。发现用户后续修改则停止，避免覆盖。回滚脚本需要同目录的 BASELINE.zip 和清单；先停止该目录的应用进程。运行数据库采用增量迁移，脚本不自动回退用户新记录。本轮升级前 SQLite 备份位于本机 `instance/backups/before-v2.db`，不进入交付包。

回滚已在独立副本执行，并运行恢复后的 V1 同一条自检；当前工作区保持 V2。详见验证文件。完整模块对照见 `PRD_COMPLETION.md`。
