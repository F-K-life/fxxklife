# 明日见 Self Echo：成长实验闭环设计规格

日期：2026-09-22
状态：待用户审阅
范围：模型回复可靠性与第一版 12 周成长实验闭环

## 1. 背景与目标

当前产品已经具备未来自我对话、目标、任务、沉浸计时、行动回响、来信、周回顾、画像与记忆等能力，但这些模块仍以并列功能存在。用户难以清楚看到“我想成为谁”如何转化为能力、练习、证据和下一轮调整。

本次改造将产品核心从“任务集合”升级为“成长实验”：用户围绕一个 12 周主题，通过每周假设、具体行动、沉浸实践、作品证据、反思和周回顾形成连续闭环。未来自我是该成长引擎的人格化交互界面，不是预言者，也不替用户作决定。

本次同时修复模型回复可靠性问题，确保被截断或结构错误的 JSON 永远不会作为聊天正文展示。

## 2. 成功标准

第一版完成后，用户可以：

1. 建立一个进行中的 12 周成长实验。
2. 确认并编辑 3—7 项能力。
3. 确认第一周唯一成长假设与关联行动。
4. 完成一次关联能力的沉浸实践。
5. 提交作品、回答、链接或反思作为成长证据。
6. 在成长地图中追溯能力与证据的关系。
7. 通过周回顾确认下一周实验。
8. 在聊天中获得引用近期真实进展的回应。
9. 在模型截断、格式错误或超时时收到安全自然语言回复，而非协议文本。

北极星行为是完成一次“方向 → 实验 → 行动 → 证据 → 回顾 → 调整”的成长闭环，不是聊天次数或累计计时分钟。

## 3. 设计原则

- 第一版每位用户最多只有一个 `active` 成长实验；其他实验只能为 `draft`、`paused` 或 `completed`。
- 复用现有目标、任务、沉浸、事件、回顾和记忆，不重写历史数据。
- 愿望不是事实，行动不是掌握，AI 观察不是用户结论。
- 用户确认后才创建任务、证据、能力结论或下一周实验。
- 所有成长结论可追溯到明确来源。
- 无成长实验的旧账号仍可使用现有功能。
- 第一版不做人格分、自律分、能力百分比、社交排行或多实验并行。

## 4. 领域模型

### 4.1 成长实验 `growth_experiments`

字段：

- `id`, `user_id`
- `title`
- `future_identity`：用户希望成为怎样的人
- `desired_outcome`：12 周结束时希望产生的真实成果
- `start_date`, `end_date`
- `status`：`draft | active | paused | completed`
- `current_week`：1—12
- `version`
- `created_at`, `updated_at`

数据库通过部分唯一索引保证每位用户最多一个 `active` 实验。默认周期为 12 周；暂停后用户可以继续原日期或显式重设周期，系统不自动延长。

### 4.2 能力 `capabilities`

字段：

- `id`, `user_id`, `experiment_id`
- `name`, `description`
- `target_state`
- `status`：`unverified | practicing | evidenced`
- `position`
- `version`
- `created_at`, `updated_at`

第一版每个实验限制 3—7 项能力。AI 只生成草案，用户可编辑、排序、删除或确认。

### 4.3 每周实验 `weekly_experiments`

字段：

- `id`, `user_id`, `experiment_id`, `week_number`
- `hypothesis`：本周准备验证的唯一成长假设
- `success_signal`：怎样的事实能说明本周获得了有价值的信息
- `status`：`draft | active | ready_for_review | reviewed`
- `version`
- `created_at`, `updated_at`

同一成长实验同一周只有一个记录；只有一个周实验可以为 `active`。

### 4.4 成长证据 `growth_evidence`

字段：

- `id`, `user_id`, `experiment_id`, `capability_id`
- `weekly_experiment_id`
- `task_id`, `session_id`, `event_id`（均可为空）
- `kind`：`artifact | answer | link | reflection`
- `content`
- `source_label`
- `status`：`active | revoked | source_missing`
- `confirmed_by_user`
- `created_at`, `updated_at`

附件第一版沿用现有资料导入能力或保存文本、链接；不引入新的大文件存储系统。

### 4.5 现有对象关系

- `goals`：继续负责方向和里程碑，可选关联成长实验。
- `tasks`：增加 `experiment_id`、`weekly_experiment_id`、`capability_id`。
- `focus_sessions`：通过任务继承成长上下文。
- `events`：记录实际结果与用户反思。
- `reviews`：增加成长实验和周次关联。
- `memories`：只保留经用户确认、来源仍有效的长期理解。

## 5. 用户流程

### 5.1 创建实验

当用户没有进行中的实验时，系统提供四步创建流程：

1. 描绘未来身份。
2. 定义 12 周真实成果。
3. AI 提出 3—7 项能力草案，用户编辑并确认。
4. AI 提出第一周假设和行动草案，用户确认。

创建请求必须幂等；并发创建第二个 `active` 实验时返回可恢复的冲突提示。

### 5.2 沟通

聊天页顶部显示当前未来身份、当前周、本周实验、最近证据和继续行动入口。模型上下文按以下优先级组织：

1. 用户本轮明确要求。
2. 当前成长实验与本周假设。
3. 最近有效行动、反思和证据。
4. 用户确认的画像与记忆。

未来自我只能依据来源表达：愿望用“你希望”，计划用“你准备”，行动用“记录显示”，作品用“你确认的证据显示”。

### 5.3 沉浸

沉浸开始前显示关联能力、本轮唯一目标、第一步、完成标准、计划时长和预期证据。沉浸过程中默认安静；用户主动选择“我卡住了”时依次提供启发问题、更小步骤和示例。

### 5.4 回响与证据

沉浸结束后先保存真实计时，再收集：

- 实际完成内容
- 作品文字、链接或资料引用
- 最大困难
- 有效方法
- 用户认为本次支持的能力
- 下一次调整

只有用户提交后才创建成长证据。一次行动没有作品或可核对结果时，能力最多进入 `practicing`；只有用户确认的有效证据才能支持 `evidenced`。

### 5.5 周回顾

周回顾汇总计划、实际行动、成长证据、重复阻碍和有效条件。系统提出下一周唯一假设草案；用户确认后创建下一周实验。生成失败不修改当前状态，可安全重试。

### 5.6 成长地图

画像页新增成长地图，展示未来身份、12 周周期、能力状态、证据数量、最近练习和来源追溯。状态只使用“尚未验证、正在练习、已有证据”，不显示能力百分比或人格评分。

## 6. 页面职责

- 沟通：澄清为什么做，并连接未来身份与本周选择。
- 沉浸：完成一个具体、可结束的实践。
- 回响：保存实际发生的结果、作品与反思。
- 画像：展示这些事实如何改变用户对自己的理解。

第一版不增加第五个主导航。成长实验摘要进入聊天页，成长地图进入画像页，周回顾与证据详情进入回响页。

## 7. 模型回复可靠性

### 7.1 根因

当前兼容模型返回被截断的 JSON 时，结构化解析失败后会进入普通文本兜底，使半截 JSON 成为 `reply_text` 并保存。前端只是展示已保存内容，错误源位于模型协议边界。

### 7.2 新处理顺序

1. 读取响应并检查大小、消息内容与 `finish_reason`。
2. 尝试解析 JSON 并校验完整协议。
3. 结构化内容无效时进行一次结构修复请求。
4. 以 `{`、`[`、JSON 代码围栏或协议字段开头的无效内容禁止进入纯文本兜底。
5. 只有明确的自然语言响应才允许作为无行动卡回复。
6. 修复失败时返回本地安全回复，并标记降级原因。
7. 只有最终有效结果可以写入消息表。

结构化验证继续检查字段集合、意图、行动卡、时长、证据引用和禁止声明。兼容服务若不支持 `response_format`，仍使用提示词与本地验证保证协议。

### 7.3 脱敏监控

记录事件类别与计数：成功、截断、解析失败、结构失败、超时、连接错误、修复成功、本地降级。监控不记录 API 密钥、完整提示词或私人正文。

## 8. 一致性与错误恢复

- AI 行动仅为建议；用户确认后才创建任务。
- 任务开始后才创建沉浸会话。
- 结束沉浸先落计时事实，再等待用户回响。
- 回响提交后才创建成长证据。
- 周回顾只读取已提交事实。
- 所有创建接口使用请求 ID 或自然唯一键实现幂等。
- 异步生成结果写回前重验用户、实验版本、画像版本、授权和来源有效性。
- 模型失败不回滚已保存的行动事实。
- 证据撤回或来源删除后标记失效，并停止支持后续 AI 结论；历史文本保留来源已调整提示。
- 数据迁移全部为增量，不删除或重写现有用户记录。

## 9. API 边界

第一版新增：

- `GET /api/growth-experiments`
- `POST /api/growth-experiments`
- `PATCH /api/growth-experiments/<id>`
- `POST /api/growth-experiments/<id>/capability-draft`
- `POST /api/growth-experiments/<id>/capabilities/confirm`
- `POST /api/growth-experiments/<id>/weekly-draft`
- `PATCH /api/weekly-experiments/<id>`
- `POST /api/growth-evidence`
- `PATCH /api/growth-evidence/<id>`

`GET /api/state` 增加当前实验、能力、当前周实验和最近证据摘要。所有接口必须通过现有账号所有权、CSRF、字段长度、版本和授权检查。

## 10. 测试策略

### 10.1 模型协议单元测试

- 截断 JSON 不进入聊天正文。
- JSON 代码围栏截断不进入纯文本兜底。
- 无效结构最多修复一次。
- 修复失败返回本地安全回复。
- 合法纯文本兼容响应仍可显示。
- 日志不包含密钥、完整用户上下文或上游错误正文。

### 10.2 领域与 API 测试

- 每位用户最多一个 `active` 实验。
- 暂停当前实验后可以激活另一个。
- 能力数量限制为 3—7。
- 不同用户不能读取或关联对方实验、能力和证据。
- 没有作品证据时不能自动标记 `evidenced`。
- 撤回或删除来源后证据停止支持 AI 结论。
- 重复请求不创建重复实验、任务、回响或证据。
- 旧数据库迁移后原有功能和记录保持可用。

### 10.3 完整流程冒烟测试

覆盖：注册或登录 → 建档 → 创建实验 → 确认能力 → 确认周实验 → 创建行动 → 开始并结束沉浸 → 提交证据与反思 → 查看成长地图 → 生成周回顾 → 确认下一周实验。

### 10.4 前端验证

- 桌面与移动宽度都可完成核心流程。
- 刷新、掉线和重试不产生重复写入。
- 聊天页不出现协议 JSON。
- 核心表单和弹窗支持键盘操作、明确标签和可恢复错误信息。

## 11. 交付拆分

### 阶段 A：可信模型边界

先修复截断 JSON、结构修复、纯文本识别、安全降级与脱敏监控，并增加回归测试。

### 阶段 B：成长实验领域层

加入实验、能力、每周实验、证据表和 API；关联现有目标、任务、沉浸、事件与回顾。

### 阶段 C：最小闭环界面

实现创建实验、聊天摘要、沉浸上下文、证据提交、周回顾和画像成长地图。

### 阶段 D：完整验证

运行单元、API、迁移、冒烟、移动端与无障碍验证；修复后再接入当前预览分支。

## 12. 明确不在第一版范围内

- 多个同时进行的成长实验
- 自动能力分数或人格分数
- 社交广场、排行、勋章和强制连续签到
- 真人导师市场
- 新的大文件或媒体存储系统
- 日历、GitHub、Notion 等第三方集成
- 多时间尺度未来自我议会
- 自动替用户创建、开始或完成行动

这些能力只能在第一版闭环有真实使用证据后单独设计。
